# 提示词增强配置与保存机制改造计划

## 需求背景
1. **Token 限制简化**：提示词增强设置面板中移除「最大输出 token」配置项，用户配置增强模型时只需选择模型与推理档位；Token 预算与限制直接根据所选模型自身的配置规格生效。
2. **显式保存机制**：设置面板不再使用“即改即存（auto-persist）”模式，改为“本地草稿（Draft）编辑 + 底部显式保存按钮”模式。修改后需点击保存，保存前进行完整性校验，未保存时提示状态，保存成功后弹出 toast 反馈。

---

## 改造方案

### 1. 设置面板改造 (`packages/ui/src/settings/PromptEnhanceSettingsPanel.tsx`)
- **移除配置项**：
  - 移除「最大输出 token」输入框及相关的 `maxOutputTokensDraft`、`commitMaxOutputTokens`、`maxOutputTokensUpperBound` 代码。
  - 面板精简为三项核心展示：开关、增强模型选择器、推理档位选择器（仅模型支持时显示）。
- **建立 Draft 状态机与 Dirty 追踪**：
  - 结构定义：
    ```ts
    interface PromptEnhanceDraft {
      enabled: boolean;
      selection: ModelSelection | undefined;
    }
    ```
  - `baseline`：自 `settings`（`promptEnhanceEnabled` 与 `promptEnhanceModel`）派生。
  - `draft`：本地 state，仅在用户点击保存前维护当前变更；开关切换、模型切换、推理档位切换均只更新 `draft`。
  - `isDirty`：深度对比 `draft` 与 `baseline`，精准识别开关、模型、推理档位是否有变更。
  - `configIncomplete`：如果 `draft.enabled === true`，校验是否已选择模型，且当模型支持档位时是否已选档位；不完整时底部显示提示文案，并禁用保存按钮。
- **新增保存操作区**：
  - 在卡片底部添加操作栏：
    - 未保存提示：`isDirty && !configIncomplete` 时提示「有未保存的更改」；
    - 不完整提示：`configIncomplete` 时提示错误文案；
    - 「保存」按钮：`<Button variant="default">`，`canSave = isDirty && !configIncomplete && !saving`；
    - 点击保存时调用 `update({ promptEnhanceEnabled: draft.enabled, promptEnhanceModel: draft.selection })`；
    - 保存成功触发 `toast(...)` 提示已保存，保存失败给出失败提示。

### 2. 增强调用优化 (`packages/ui/src/hooks/usePromptEnhance.ts`)
- 移除对 `settings?.promptEnhanceMaxOutputTokens` 的依赖和 5000 硬编码。
- 调用 `zcodeAgentService.generateWorkspaceText` 时不再传递 `maxOutputTokens`，直接由底层模型配置与运行时默认预算自适应约束。

### 3. 国际化与设计文档同步
- **国际化 (`packages/ui/src/i18n/locales/{zh-CN,en-US}.ts`)**：
  - 增加保存按钮相关文案：`settings.promptEnhance.save`（保存）、`settings.promptEnhance.saved`（已保存提示词增强设置）、`settings.promptEnhance.saveFailed`（保存失败）、`settings.promptEnhance.unsavedChanges`（有未保存的更改）。
- **设计文档 (`docs/prompt-enhance.md`)**：
  - 同步更新产品决策：移除用户手动配置 Token 上限，说明改为自适应模型规格；
  - 补充设置面板的显式保存交互规则。
